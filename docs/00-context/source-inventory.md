## Current Implementation Evidence Boundary

The existence of the deployed Ubuntu Capital website and the identity of the stated implementation repository are part of the reconstruction context. Those confirmed identities do **not** prove the repository's current contents or which of the 41 catalogued use cases are fully implemented, partially implemented, simulated, or absent.

Repository artifacts record a local inspection of an unpinned snapshot that described a front-end portal with route-based pages for discovery, dashboard, onboarding, opportunities, portfolio, reports, and investor/account flows, plus mock opportunity data and UI state. Because the exact branch, commit SHA, run identity, and durable raw-evidence reference are missing, those observations are historical and partial only. They do not confirm current repository behaviour, the current absence of backend/API/database/authentication/payment components, or present implementation status.

The historical failed connector attempt is recorded as `CONFIRMED` evidence of that attempt's access outcome with delivery status `BLOCKED_BY_CONTEXT`. It must not be classified as `CONTRADICTED`, and it must not be presented as the current connector-access state without a new attempt.

The use-case coverage artifacts partially describe the reported unpinned snapshot. They remain historical supporting evidence and cannot establish current coverage until an authorised, revision-pinned reinspection records the source revision, run identity, durable evidence, and backend/persistence/operational reconciliation.
